# 영상 평가 기준

## 판정
- **위험**: 사실 오류(지어낸 수치, 실명·키·비공개 이름 노출, 범위와 부딪치는 주장), 보는 사람이 바로 알아챌 결함(흰 번쩍임, 4겹 글자, 빈 화면, 글꼴 폴백, 잘린 글자), 사양 실패 여러 개.
- **보통**: 원칙 위반이나 사양 실패가 있지만 국소적이다. 부자연스러운 설명 문장, 짧은 머무는 시간, 이음새 튐, 6초 넘는 정지 구도 등.
- **통과**: check.sh 통과, 사실 오류와 원칙 위반 없음. 남은 것은 취향("참고")뿐.
- 부자연스러운 설명 문장은 사실 오류가 아니어도 통과를 막는다(사용자가 직접 지적한 항목).
- 취향 문제로는 막지 않는다.

## 방법
- 산출물 수치: `check.sh`. 없으면 아래 명령으로 잰다.
  ```bash
  ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,sample_rate:format=duration,size -of compact intro.mp4
  ffmpeg -nostats -i intro.mp4 -af ebur128=peak=true -f null - 2>&1 | grep -E "^ +(I|Peak):"
  ffmpeg -i intro.mp4 -vf freezedetect=n=-60dB:d=2 -an -f null - 2>&1 | grep freeze_start
  ffmpeg -i intro.mp4 -vf "fps=4,scale=320:-1,tile=8x6" tiles_%02d.jpg
  ```
- 본편은 0.25초 타일로 처음부터 끝까지 본다. 빠른 이동 구간, 헤드라인 구간, 설명 구간은 원본 크기 프레임을 연다.
- 썸네일은 처음 3프레임과 끝 3프레임을 나란히 보고, 1200×630에서 가운데 880px 밖에 핵심이 없는지, 400px 폭으로 줄여도 무슨 프로젝트인지 보이는지 본다.
- 소리는 들을 수 없으니 수치(음량, true peak, 48kHz)를 재고, 소스(`buildAudio`)에서 큐 시각이 화면 사건과 맞는지 본다.

## 항목

1. 사실 (principles.md P9~P22)
   - 화면 문구와 장면이 기획서, 원본 자료와 맞는가.
   - 지어낸 수치·점수·수상, 실명, 회사·기관명, 키·IP·도메인, 비공개 저장소 이름이 있는가.
   - 실물 화면에 수치나 라벨이 남았는가.
   - 서로 다른 실행을 연속 카운터로 이었는가. 원문 숫자와 단위를 바꿨는가.
   - 지금도 돌아가는 것처럼 보이는 표시나 출시된 앱처럼 보이는 연출이 있는가.
   - 과장은 허용하지만 범위 제한과 정면으로 부딪치는 연출은 안 된다.
2. 기획서 이행
   - 장면 순서, 헤드라인 문구, 엔딩, 바탕 톤이 기획서와 같은가. 달라졌다면 이유가 타당한가.
   - 여러 단계 프로젝트라면 전체 과정을 다 보여 주는가(P8).
   - 기준 예제(`templates/intro.src.html`)의 겉모습을 그대로 썼는가. 점·선반·원 그림, 어두운 설명 상자, 원으로 밀려 들어가는 엔딩, 종이색 바탕을 그대로 쓰면 지적한다(P23~P26). 예제의 규약(seek, 속도 곡선, 머무는 시간, 루프 주기)을 따른 것은 지적하지 않는다.
3. 화면 품질 (P27~P32, P39~P50)
   - 720p에서 설명 본문 20px, 이름 24px, 보조 글씨 14px 이상인가.
   - 잘림, 겹침, 교차 페이드 글자, 4겹 글자, 빈 화면, 흰 번쩍임, 밝기 튐, 글꼴 폴백, 남은 상태 표시, 비치는 뒤 층이 있는가.
   - 화면이 멈춰 있지 않은가. 같은 구도로 6초 넘게 서 있는 곳이 있는가.
   - 헤드라인과 정보가 다 들어온 뒤 1초 이상 보이는가.
4. 설명 (copy.md)
   - 장면별 판단이 타당한가. 필요한데 빠진 장면, 필요 없는데 붙은 장면을 짚는다.
   - 한 영상 안에서 모양이 하나로 통일됐는가. 섞였다면 이유가 있는가.
   - 모양이 주제에 녹아 있고 색, 글꼴, 동작, 소리까지 그 모양다운가.
   - 머무는 시간이 글자 수를 11로 나눈 초(최소 2초) 이상인가. 등장과 퇴장이 0.5초 안인가. 설명 중에도 장면이 움직이는가.
   - 설명이 그림이나 헤드라인과 겹치지 않고, 다음 설명 전에 완전히 빠지는가.
5. 문장 자연스러움 (copy.md, 막는 항목)
   - 한 줄씩 소리 내어 읽듯 확인한다.
   - 대응표식 나열, 명사 나열, 번역투, 딱딱한 전문어, 구현 명세 읽어 주기, 추상 명사, 숫자, 마침표, "~다"·"~요" 끝이 있으면 지적하고 고친 문장을 함께 적는다.
   - 두 줄이 "일어나는 일 + 얻는 것"인가. 얻는 것이 자료에 있는 것인가.
   - 헤드라인: 12자 안팎, 설명조 없음, 모호한 낱말 없음.
6. 썸네일 (P51~P56)
   - 본편에서 그대로 잘라 낸 구간인가. 첫 프레임이 빈 화면이 아닌가.
   - 이음새에 글자가 걸리지 않고, 양 끝의 요소·카메라·크기가 같은가.
   - 썸네일 처음/끝 프레임이 마스터의 같은 시각과 같은가(P55). check.sh에 `VS_MASTER`를 주면 SSIM으로 재고, 마스터가 없으면 `thumb-seam.jpg`에서 저비트 잔상, 유령 글자, 흐린 이음새를 눈으로 본다.
   - 가운데 880px, 400px 축소, 용량, 무음, 설명 없음.
7. 소리 (P57~P61)
   - -16 LUFS 안팎(기본 ±1), -1 dBTP 이하, 48kHz.
   - 큐 시각이 화면 사건과 맞는가. 설명 모양다운 등장 소리인가.
8. 기획서 평가일 때 (영상이 아직 없을 때)
   - 위 1, 2, 4, 5, 6을 기획서 문구와 장면표로 본다.
   - 형식, 엔딩, 바탕 톤이 기본 틀(P23, P25, P26)에 기대지 않는가.
   - 가림 목록이 하나씩 적혀 있는가(P22). 썸네일 구간과 이음새 처리가 장면표 시간과 맞는가.

## 출력 (한국어)

```
판정: 위험 | 보통 | 통과

## 막는 문제 (심각도 순)
1. [12.4초] 무엇이 문제인지. 근거(P번호 또는 사양). 고칠 방향.

## 참고 (취향, 막지 않음)
- ...

## 확인한 것 / 못 한 것
- check.sh: 통과 19/19 (또는 실패 항목)
- 못 한 것: (예: 원본 자료 없음, 소리는 수치만)
```
- 판정은 첫 줄에 쓴다.
- 지적마다 시간(초), 문제, 근거, 고칠 방향을 적는다. 문장 지적에는 대안 문장을 함께 적는다.
