# 프롬프트 순서도 (바이브코딩 워크플로)

---

## PHASE 0 — 리서치

**목적:** 구현 전에 선행 지식을 문서화한다.

```
관련 논문/자료를 '상세히, 깊이 이해, 깊이 읽고' 정리해서 research.md 만들어줘.
핵심 개념, 수식, 한계점, 나에게 적용 가능한 부분을 섹션으로 나눠줘.
```

- "상세히", "깊이"를 명시하지 않으면 요약본만 나온다.
- 논문 URL이나 파일 경로를 직접 넘겨줘야 정확하다.
- 산출물: `research.md` (이후 plan.md의 근거 자료로 쓴다)

---

## PHASE 1 — 계획 수립

**목적:** 코드 한 줄도 쓰기 전에 전체 설계를 문서로 굳힌다.

```
~~를 해야 함.
이를 위한 상세 plan.md 작성해줘.
코드 스니펫도 포함해줘.
소스 파일 읽고 실제 코드베이스 기반으로 계획 작성해.
```

### 좋은 plan.md가 갖춰야 할 것

| 섹션 | 내용 |
|------|------|
| 목표 | 한 문장으로 명확한 완료 기준 |
| 전제 조건 | 이미 존재하는 것, 건드리지 않을 것 |
| 단계별 계획 | 번호 붙인 단계 + 각 단계의 검증 방법 |
| 코드 스니펫 | 핵심 함수 시그니처, 타입, 패턴 미리 작성 |
| 리스크 | 예상 막힐 지점 + 대안 |

> **코드 스니펫 포함 이유:** 자주 쓰는 패턴을 상용구처럼 미리 정의해두면
> 구현 단계에서 모델이 일관된 스타일로 코드를 생성한다.

### 주석 확인 단계 (선택)

```
코드 확인 후 주석 달기 → 필요한지 안 필요한지에 대한 설명 포함해줘
```

- 주석이 "무엇"을 하는지 설명하면 제거 대상
- 주석이 "왜" 이렇게 했는지 설명하면 유지 대상

### 메모 반영 루프

```
문서에 몇 가지 메모를 추가했어.
모든 메모 반영하고 문서를 업데이트해.
아직 구현하지마.
```

- 만족할 때까지 이 사이클을 반복한다.
- 계획이 안정될 때까지 구현을 시작하지 않는 것이 핵심.

## PHASE 2 — 구현

**목적:** 계획을 실제 코드로 변환한다.

```
전부 구현해라.
작업이나 단계를 완료하면 계획 문서에서 완료로 표시해라.
모든 작업과 단계가 완료될 때까지 멈추지 마라.
any나 unknown 타입을 쓰지 마라.
지속적으로 typecheck를 실행해서 새로운 문제를 만들지 마라.
```

### 구현 시 필수 규칙

| 규칙 | 이유 |
|------|------|
| `any` / `unknown` 금지 | 타입 안전성 붕괴 방지 |
| 단계 완료 시 즉시 체크 표시 | 진행 상황 추적, 재작업 방지 |
| typecheck 상시 실행 | 새 오류가 쌓이기 전에 잡는다 |
| 완료 전 멈추지 않기 | 중단 시 컨텍스트 손실 발생 |

### 구현 루프 흐름

```
구현 → typecheck → 오류 수정 → 단계 체크 → 다음 단계
```

## PHASE 3 — PLANNER / EVALUATOR / DEVELOPER 구조

**목적:** 복잡한 작업을 역할 분리로 품질을 높인다.

```
PLANNER → EVALUATOR → DEVELOPER 구조로 설정해줘
```

### 각 역할 정의

**PLANNER**
- 전체 작업을 작은 단위로 분해
- 각 단위의 입력/출력/검증 기준을 명시
- 의존성 순서 정의

**EVALUATOR**
- PLANNER가 만든 계획의 논리적 허점 검토
- "이 단계는 왜 필요한가?", "더 단순한 방법은?"
- 계획을 실행하기 전에 한 번 더 검증

**DEVELOPER**
- PLANNER + EVALUATOR가 검토한 계획을 코드로 변환
- 계획 외 추가 기능 구현 금지
- typecheck, lint 통과 후 단계 완료 처리

### 프롬프트 예시

```
너는 지금 세 역할을 순서대로 수행할 거야:

1. PLANNER로서: ~~기능을 구현하기 위한 단계별 계획을 작성해.
   각 단계에 검증 방법을 포함해.

2. EVALUATOR로서: 위 계획을 검토하고 문제점이나 단순화 가능한 부분을 지적해.

3. DEVELOPER로서: 검토된 계획대로 구현해.
   any 타입 금지, 각 단계 완료 시 계획에 체크 표시.
```

---

## 전체 워크플로 요약

```
PHASE 0: 리서치 → research.md
    ↓
PHASE 1: 계획 수립 → plan.md (메모 반영 루프)
    ↓
PHASE 2: 구현 → 코드 (typecheck 루프)
    ↓
PHASE 3: (복잡한 작업) PLANNER → EVALUATOR → DEVELOPER
```
